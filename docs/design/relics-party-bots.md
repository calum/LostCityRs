# Congratulating bot players after the final wave

**Question this answers:** how do a crowd of famous-named "players" appear after the bonus boss fight, follow the players, and shout old school congratulations; what are they; how do I test and tune them.

**Based on:** root `7d96635` + this change, Engine-TS `cd2f9e8c` (unchanged), Content `7602b1c0e` (pack ids only). **Method:** built test-first in the headless harness (`tests/relic-party.test.ts`, 5 tests). The first run of the new tests failed (missing script and npc types, plus two mistakes in my own test set-up); after implementing, 5/5 pass and the full suite is 460/460 (Node 24.11.1, `node harness/run.mjs`). **Nothing was seen in a real client**: how the outfits look, how the crowd moves and how the overhead text reads are not covered by the harness.

## What it is (decision)

The bots are **server-side cosmetic NPCs**, not real logins. Why: a real `Player` would be saved, counted, attackable and tradeable; the engine has no fake-player concept (not searched exhaustively: no hit for a bot/fake flag in `Engine-TS/src/engine/entity/Player.ts`). They have no options, so there is no trade/attack/talk entry, and `blockwalk=none` so 40 of them cannot trap a player. Name floats only on right-click Examine (NPCs have no name over their head); chat is overhead text only, not in the chat box.

## Behaviour

1. **Trigger.** `[proc,relic_bonus_arm]` (end of `[proc,relic_on_kill]`, `mods/relics/scripts/relic_bonus.rs2`) now also runs for a dying `kalphite_flyingqueen` in the lair (a Kalphite Queen only dies for good in her flying form, `docs/design/relics-bonus-boss-fight.md`). While the fight's glow controller exists, each such death adds an invisible `relic_bonus_kill` marker; the fourth marker deletes the markers and adds a `relic_party_timer` npc for 3 ticks. Markers are also cleared at the start of each round. **Inference/limit:** it counts four deaths of KBD or flying KQ, it cannot tell the bonus bosses from the respawned static KBD (150 ticks after the first kill), so if the static one is killed during the fight the party can start one boss early.
2. **Party start.** `[ai_despawn,relic_party_timer]` calls `~relic_party_start(0_42_153_32_20, 16, true, 40)` (`mods/relics/scripts/relic_party.rs2`): counts players in the lair box (same rule as the glow), then for each of 40 bots picks one of those players uniformly at random (a second `huntall` pass walks to the k-th player) and spawns the bot on a free tile 1-3 away with a smoke puff. If nobody is alive in the lair, nothing spawns.
3. **Names.** Consecutive entries from a random start in a list of 61 names, so there are no repeats within a party (up to 61 bots). 23 are real OSRS creators, 38 are invented joke names (`REAL` / `JOKE` in `scripts/gen-relic-party.mjs`). **The real names are from memory**: the wiki guide Calum linked and any Twitch/Kick ranking could not be fetched from the cloud sandbox (host not allowed / no DNS), so the requested lists were not used. Extend `REAL` from the wiki page and the streamer lists.
4. **Appearance.** `scripts/gen-relic-party.mjs` (seeded, deterministic) dresses each name from real `manwear` models of obj configs in Content (hat/body/legs/feet/hands/weapon/shield/cape pools of 100/61/58/20/19/242/36/21 items), a random hair + beard model, and at most 6 colour swaps (gear recolours first). Output: `mods/relics/configs/relic_party.npc/.enum/.constant`. Rerun the script after editing names or lines and commit the output.
5. **Chat.** 78 lines in OSRS speak ("gz", "rip bank", "where is my cut?", "trading 100 mith bars 200ea", "o7"...) in `relic_party_msgs`. Each bot says one on arrival and, every 6 ticks (`timer=6`), one time in two. Category script `[ai_timer,_relic_party]` also re-issues `npc_setmode(playerfollow)` because a bot that gets stuck in the crowd drops follow mode (`Engine-TS/src/engine/entity/Npc.ts` ~l.880: stuck counter then `resetDefaults`); the followed player is stored in npc varn `relic_party_target`.
6. **Leaving.** 250 ticks (2.5 min) after spawning the npc despawns with a smoke puff (`[ai_despawn,_relic_party]`).
7. **Debug.** `::~relic_party` spawns 40 around the caller (anyone within 16 tiles is a possible target), anywhere. Dev commands are off on a public `ACCESS_CODE` host, so it is not available there.

## Edits outside mods/

Content `pack/npc.pack`: ids 1360-1423 for the 61 `relic_party_N` types, `relic_bonus_kill`, `relic_party_timer` (Content `7602b1c0e`, pushed to the fork; generated by `scripts/sync-mods.mjs`). No engine change.

## Facts learned

- Bots on the player's tile or around them stop the player from walking unless `blockwalk=none` (the test could not path out of the crowd).
- NPC categories work for scripts: `[ai_timer,_<category>]` / `[ai_despawn,_<category>]` run for every type with `category=<category>`.
- A harness bot left in the world is a valid follow target for later tests in the same file; the tests remove their bots in `afterEach`. Bosses kill unarmoured bots within ~10 ticks, so the fight test heals the bots each tick.
